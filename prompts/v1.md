# Prompt v1

Primeira versão, usada no fluxo `workflow/fluxo-v1.json`.

| Item | Valor |
|---|---|
| Modelo | GPT-4o mini |
| Entrada | Texto de uma vaga pública, colado no formulário |
| Perfil usado na análise | Candidata fictícia (sem dados pessoais) |

## Prompt (mensagem de sistema)

```
Você analisa vagas de emprego para uma candidata fictícia com
este perfil: analista júnior com conhecimento em SQL, Power BI,
Python básico, automação com ferramentas no-code e experiência
com documentação e processos.

Dada a vaga abaixo, responda APENAS com JSON válido, sem texto
antes ou depois, com estes campos:
- empresa
- cargo
- resumo (2 frases)
- requisitos (lista dos principais)
- aderencia (lista de objetos com "requisito" e "status",
  onde status é: atende, parcial, nao_atende ou indeterminado)
- riscos (lista)
- observacoes

Regras: não invente informações que não estejam na vaga.
Se algo não estiver claro, use "indeterminado".
```

A mensagem do usuário contém apenas o texto da vaga.

## O que foi observado

1. A resposta veio dentro de um bloco de código (` ```json `), apesar de o prompt pedir só JSON. Isso impede a leitura automática pela planilha. O nó de tratamento passou a remover essas marcações.
2. A lista de requisitos às vezes ficou incompleta: ferramentas citadas como "quando necessário" apareciam só nas observações.
3. Quase todos os requisitos saíam como "atende", e não havia justificativa para os status.
4. Rodando a mesma vaga duas vezes, `riscos` e `observacoes` mudaram.
5. Os riscos misturavam fatos do anúncio com interpretações (por exemplo, tratar o modelo híbrido como "inadequado").
6. Localização e modelo de trabalho não eram avaliados, porque o perfil não informava cidade.

As mudanças feitas a partir daqui estão em [historico-de-versoes.md](historico-de-versoes.md).
